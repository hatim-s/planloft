# Planloft 1.2.0 release plan

Planloft 1.2.0 adds document-specific reader preferences for color scheme and page
width. Existing browser preferences become site defaults. Readers can edit those
defaults in Appearance settings and reset either document preference independently.
With no saved preferences, Planloft uses system color and reading width.

Render local documents again to get the new controls. Published HTML needs an
explicit redeploy. A newly rendered page on the same site can still read the
reader's existing site defaults.

## Before publishing

- Fast-forward the dedicated `release` checkout to the merged `origin/main` and
  confirm the checkout is clean.
- Serve two freshly rendered documents at different paths on the same origin.
  Seed the old `planloft-color-scheme` and `planloft-layout` browser keys and confirm
  that the new pages use them as site defaults. Verify that color and width persist independently after reload, that a second
  document inherits the site defaults, and that resetting either setting reveals
  its default. Include a trusted HTML render and a gallery preview. Reopen a
  stored document with `planloft preview` and verify that its choices persist
  across `file://` opens. Check that local files keep separate document settings
  when the browser allows local-file storage.
- Re-render HTML generated by 1.1.0 with `--trusted-html` and check that it has
  one updated controls block and preserves the original content.
- Check the Appearance settings menu at narrow width and with keyboard navigation.
  Enter opens it, Escape closes it and returns focus to the trigger, and clicking
  outside closes it. Repeat in Chrome and Safari. Verify that gallery toolbar
  choices leave saved preferences alone.
- Confirm the npm account can publish `planloft` and that the version and tag are
  available. Use Node.js 22.15.0 or newer.

## Publish when approved

Run `bun run release 1.2.0` from the synchronized checkout. The command runs
the source, type, package, and installer gates, publishes the verified tarball,
and pushes `v1.2.0`. Verify the npm version, Git tag, and remote installer
results afterward. See the [release guide](../releasing.md) for retry behavior.
